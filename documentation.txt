2.5 Git Workflow & Branching
---------------------------------------------
- main: The stable production branch containing tested, compiling code.
- Feature Branches: Parallel sandbox branches (e.g. git checkout -b feature/name) 
  used to build new components without risking the stability of main.
- Basic Commands:
  - git add .                  : Stage all file changes
  - git commit -m "Message"    : Save local snapshot of staged files
  - git push                   : Upload local commits to remote GitHub repository
  - git checkout -b <branch>   : Create and switch to a new feature branch
  - git merge <branch>         : Merge finished feature code back into main

4.2 Medium Level Summary (Thread & Execution Model)
----------------------------------------------------------------------
The system operates across two isolated CPU execution threads:
1. Real-Time Audio Thread (AudioEngine):
   - Triggered asynchronously by hardware interrupts when MIDI bytes arrive.
   - Executes handleIncomingMidiMessage() without memory allocations or locks.
   - Writes directly to std::atomic member variables in MidiState using 
     std::memory_order_relaxed for zero CPU memory fencing stalls.
2. Main Message Thread (GUI Thread - MidiMonitorView):
   - Executes a 30 Hz juce::Timer callback (~33ms intervals).
   - Atomically reads MidiState variables.
   - Performs a state diff (compares cached lastNote vs new note).
   - Triggers repaint() only when changes occur, rendering note names (e.g. "C4"), 
     MIDI note integers, velocity meters, and active gate badges.

    Note over MS: Atomic store (0 CPU memory stalls)

    loop Every 33ms (30 Hz)
        GT->>MS: load() active note & velocity
        MS-->>GT: Returns (isNoteActive=true, note=60, vel=0.85)
        alt State Changed?
            GT->>GT: Calculate note name ("C4")
            GT->>SCR: repaint() Gate Open, Note C4, Velocity 85%
        end
    end

    HW->>AT: Physical Key Released (NoteOff C4)
    AT->>MS: noteOff(60) via std::memory_order_relaxed
    Note over MS: Atomic store (isNoteActive=false)

    GT->>MS: load() active note
    MS-->>GT: Returns (isNoteActive=false)
    GT->>SCR: repaint() Standby ("Waiting for input...")
